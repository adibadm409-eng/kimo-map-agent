# عقد التعديل الذري لبوابة Kimo

## الهدف

تعديل سجل واحد أو مجموعة سجلات محددة دون إعادة كتابة الحقول غير المستهدفة، ودون احتمال تطبيق patch على معرف عابر من كيان آخر.

## المسار الإلزامي

| المرحلة | السلوك | شرط القبول |
|---|---|---|
| تحديد الهدف | قراءة القسم والبحث عن السجل بالاسم أو الهوية الطبيعية | معرف واحد مؤكد، أو سؤال توضيحي عند التعارض |
| قراءة الحالة | `get` للسجل بالمعرف المؤكد | الحالة الحالية محفوظة للمقارنة |
| تطبيع الحقول | استخدام مخطط الكيان نفسه فقط | لا حقول project-only في properties/clients/offers/viewings |
| المعاينة | حساب before/proposed/changedFields | لا كتابة عند حقل مجهول أو سجل غير موجود |
| التطبيق | `mutate_record(update)` ببيانات patch فقط | نجاح قاعدة البيانات للمعرف المقروء نفسه |
| التحقق | إعادة `get` ومقارنة الحقول المستهدفة وغير المستهدفة | كل الحقول المطلوبة تطابق، وغير المستهدفة لم تتغير |
| التقرير | بيان ما تغير فعلاً وما فشل وما ينتظر | لا إعلان اكتمال دون نتيجة القراءة الأخيرة |

## قواعد ذرية

التعديل الذري يعني أن فشل التحقق من الهوية أو الحقول أو المعاينة يمنع الكتابة تماماً. وإذا كان الطلب يضم عدة سجلات، فكل سجل يمر بهذا المسار بصورة مستقلة؛ لا يجوز استخدام معرف سجل سابق لتعديل سجل لاحق. يجب أن تحمل نتيجة الأداة `entity` و`id` و`changedFields` وقراءة ما بعد التنفيذ، حتى يستطيع الوكيل والمستخدم تمييز الأثر الفعلي من الوعد النصي.

تظل بوابة `mutate_record` هي السطح العام للإنشاء والتعديل والحذف. لا تظهر أدوات CRUD القديمة للمهارات. تبقى الأدوات المتخصصة فقط للعمليات التي ليست CRUD عادية، مثل إنشاء عرض مع عدة تنبيهات، أو تسجيل دفعة مالية، أو استيراد مشروع هرمي، أو إدارة جدول حر. لا تُستخدم أدوات المجال المتخصصة لتجاوز قراءة الهوية أو التحقق اللاحق.

## حالات الرفض الصريح

يُرفض التنفيذ إذا كان المعرف غير موجود، أو كان الكيان لا يطابق المعرف، أو احتوى patch حقولاً مجهولة، أو احتوى التعديل حقولاً مشتقة/مالية محمية، أو تغيّرت حقول غير مستهدفة بعد التطبيق. في هذه الحالات تعاد حالة فشل قابلة للتفسير، ولا يُعاد المحاولة بمعرف مخمّن أو باستدعاء أداة أخرى عشوائياً.
