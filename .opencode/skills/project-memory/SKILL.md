# Project Memory & Change Tracking

## متى تُستدعى
- عند بدء أي عمل في مشروع مدير العقارات (~/my-app).
- عند أي سؤال عن التاريخ: "تذكر"، "ما ذا فعلنا"، "ما تغيّر"، "راجع التعديلات".
- بعد إنجاز مهمة لتحديث الذاكرة.

## البروتوكول

### 1. القراءة (بدء الجلسة أو عند السؤال عن الذاكرة)
1. اقرأ `memory/INDEX.md` — خريطة الملفات وما يحتويه كل ملف.
2. اقرأ الملفات المطلوبة للسياق:
   - `memory/ARCHITECTURE.md` — البنية والأجزاء الأساسية.
   - `memory/DECISIONS.md` — القرارات المهمة وأسبابها.
   - `memory/SESSION_LOG.md` — سجل الجلسات (الأحدث في الأسفل... أو الأعلى حسب اصطلاح الملف).
   - `memory/CHANGELOG.md` — السجل التلقائي للالتزامات.
3. افحص الوضع الحالي: `git log --oneline -20` و `git status --short`.
4. عند طلب "راجع التعديلات": افحص `git show <hash>` أو `git diff HEAD~N..HEAD`
   ثم لخّص للمستخدم ما تغيّر ومتى ولماذا، مرتبطاً بملفات الذاكرة.

### 2. التحديث (بعد إنجاز مهمة)
1. أضف إدخالاً في `memory/SESSION_LOG.md`: التاريخ، ملخص التنفيذ، الملفات المتأثرة،
   أي درس مستفاد.
2. إن وُجد قرار جديد (أو تغيّر اتجاه) أضفه في `memory/DECISIONS.md`.
3. إن تغيّرت البنية أضف/حدّث `memory/ARCHITECTURE.md`.
4. إدخالات `CHANGELOG.md` تُضاف تلقائياً عبر خطاف `post-commit` — لا تكتبها يدوياً.

### 3. الالتزام
- ذاكرة المشروع جزء من المستودع: بعد تحديث الذاكرة وافق عليها مع المستخدم ثم
  `git add memory/ AGENTS.md .opencode/` و `git commit` و `git push` عند الطلب.
- لا ترفع أسراراً؛ افحص `git status` قبل أي push.

## ملاحظات
- ملفات الذاكرة مكتوبة بالعربية (باستثناء أسماء الملفات).
- أي خطأ جذري يُوثَّق في `PROBLEMS_LOG.md` (الملف الأساسي للدروس الفنية) وليس في الذاكرة.
