# متطلبات الإدخال الصوتي لكيمو — مسار تابع

## قرار النطاق

الإدخال الصوتي ليس جزءاً من دورة TaskRun نفسها؛ هو **طبقة إدخال** تنتج نصاً أو مرفقاً صوتياً ثم تمرر الناتج إلى نفس موجه النوايا والمهارة وبوابة الأدوات. لذلك لا يحق لمسار التسجيل الصوتي تغيير حالة المهمة أو تجاوز التحقق أو اختيار مزود غير قادر.

## مصفوفة الدعم الأولية

| المزود | النمط المدعوم | ما يمكن اعتماده في التطبيق | ملاحظات التوافق |
|---|---|---|---|
| OpenAI | تفريغ ملف صوتي أو إدخال صوتي لنموذج صوتي | تسجيل ملف محلي ثم تفريغه أو إرساله إلى نموذج صوتي محدد | لا يجوز إظهار زر الصوت لكل موديلات النص؛ يجب ربطه بملف قدرات النموذج |
| Google Gemini | فهم الصوت وإنتاج نص، مع إدخال inline أو Files API | رفع/إرسال تسجيل قصير إلى مسار Gemini الصوتي أو تحويله إلى نص | صفحة الصوت الرسمية تميز بين فهم الصوت وLive API وSpeech-to-Text المتخصص |
| Mistral | Speech Transcription عبر Voxtral، مع offline/realtime | تفريغ التسجيل إلى نص ثم تمريره إلى كيمو | يدعم العربية ضمن اللغات المذكورة في وثائق التفريغ؛ هذا لا يعني أن كل موديلات Mistral النصية تقبل audio input |
| DeepSeek | لا يُفترض دعم إدخال صوتي مباشر في واجهة الدردشة الحالية | يمكن دعم الصوت فقط عبر مسار تفريغ منفصل موثق لاحقاً | يجب ألا يعرض التطبيق الخيار تلقائياً |
| Alibaba/DashScope | يعتمد على API/model capability المحددة | لا يُفعّل إلا بعد اختبار endpoint والموديل فعلياً | لا يكفي كون البوابة OpenAI-compatible لإثبات دعم الصوت |
| OpenRouter | يختلف حسب النموذج الممرر | لا يعرض إلا نماذج مسجلة كقابلة للصوت في قائمة ثابتة أو نتيجة capability probe | اسم المزود لا يثبت قدرة النموذج |
| NVIDIA NIM | يختلف حسب النموذج وendpoint | يحتاج capability profile خاصاً بالموديل | لا يُفعل افتراضياً ضمن مسار النص |
| Custom | غير معلوم حتى يختبره المستخدم | زر فحص توافق منفصل، ولا يظهر صوت قبل نجاحه | نتيجة الفحص لا تمنح صلاحية دائمة دون حفظ capability profile |

## شروط التنفيذ المقبول

لا يُضاف اعتماد الصوت إلى التطبيق إلا بعد تحديد مسار واضح: تسجيل محلي، صيغة الملف، حد الحجم والمدة، آلية التفريغ، سياسة حذف الملف بعد الاستخدام، ورسالة خطأ قابلة للفهم. ولا يجب حفظ التسجيلات الدائمة افتراضياً؛ يكفي الاحتفاظ بالنص الناتج وسجل metadata اختياري.

في إعدادات المزودات، يجب عرض ثلاثة مستويات لا مستوى واحداً: **يدعم إدخال صوت مباشر**، **يدعم تفريغاً صوتياً منفصلاً**، و**غير مثبت/غير مدعوم**. كما يجب إظهار اسم النموذج لا اسم المزود فقط، لأن بعض المزودات تجمع نماذج صوتية ونصية في واجهة واحدة.

## مرجع التحقق

تذكر وثائق OpenAI أن إدخال الصوت يمكن أن يكون جزءاً من Chat Completions مع نموذج صوتي، وأن نماذج الصوت ليست مرادفة لجميع نماذج النص.[1] وتذكر وثائق Gemini أن النموذج يستطيع فهم الصوت وإنتاج نص، مع مسارات inline وFiles API وLive API وSpeech-to-Text المتخصص.[2] أما وثائق Mistral فتفصل بين Voxtral Mini Transcribe V2 للتفريغ الدفعي وVoxtral Realtime للتفريغ اللحظي، وتذكر دعماً متعدد اللغات يتضمن العربية.[3]

## قرار التنفيذ

سيبقى هذا الملف وقائمة القدرات اختباراً ومتطلباً معمارياً في الوقت الحالي. لن تُثبت مكتبة تسجيل أو تُضاف شاشة صوتية قبل اكتمال دورة TaskRun واختبار المهام العقارية والمزودات، حتى لا يتحول الصوت إلى مسار مستقل غير منضبط.
